## Discoveries

- **DEF-01 true root cause**: `position p=1` in `xfce4-panel.xml` maps to `SNAP_POSITION_E` in xfce4-panel 4.20.7 (`panel-window.c` enum: NONE,E,NE,EC,SE,W,NW,WC,SW,NC,SC,N,S → 0..12). `panel_window_screen_struts_edge()` requires `autohide==NEVER && struts_enabled` AND a snap position that maps to an edge — for horizontal panels only N*/NE/NW (top) and S*/SE/SW (bottom); E/W/EC/WC → `STRUTS_EDGE_NONE`. `p=1` rendered top-left only because `position-locked` pins x,y — the snap semantic was wrong, not the flag.
- `disable-struts` was renamed `enable-struts` in xfce4-panel ≥4.19 with inverted migration; 4.20.7 on Ubuntu resolute writes `enable-struts` in the live channel.
- `xfce4-panel -r` / `-q` client calls are synchronous dbus calls that open a **blocking GTK error dialog** when the call fails (no instance / bus unreachable) — never use them unguarded in scripts: wrap in `timeout`.
- Session dbus is unreachable from a second `proot-distro login` (peer-credential rejection: "The connection is closed"). A respawned `xfce4-panel` dies in `xfconf_init` without a usable bus — so a kill+respawn fallback must first probe `xfconf-query -l`, else the desktop is left with no panels.
- XFCE processes inside the proot distro run as user `ubuntu`, not `test`.
